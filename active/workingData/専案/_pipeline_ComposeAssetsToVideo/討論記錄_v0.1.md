## 系統定位

以 AI 輔助為核心的影片內容製作流水線，目標是產出高品質影片與圖片素材。

**核心原則**：
- **半自動化**：關鍵節點保留人工審核，確保產出一致性
- **工具混用**：Figma + Adobe 全家桶 + HTML 各司其職，迭代各自強項
- **模組解耦**：每個能力獨立存在，可跨場景複用，此流水線只做串接與驗證
- **可擴展**：現階段服務自己（使用者本人），未來保留讓客戶直接輸入需求的空間

## 資料流初稿

```
[需求輸入]
  使用者 / 客戶需求（文字描述）
        ↓
[稿子生成]（AI 輔助，oral-script 技能）
        ↓ ← ✋ 人工審核①：稿子方向確認
[視覺模板選擇 / 建立]（Figma）
        ↓ ← ✋ 人工審核②：版型確認
[內容填入模板]（Figma Variables + AI）
        ↓ ← ✋ 人工審核③：內容準確性確認
[匯出至 Adobe]（Figma → Illustrator 插件）
        ↓
[精修 / 動畫製作]（AI + Illustrator / After Effects）
        ↓ ← ✋ 人工審核④：視覺與動畫確認
[組裝影片]（Premiere：畫面 + 語音 + 字幕）
        ↓ ← ✋ 人工審核⑤：最終成品確認
[輸出]
  ├─ MP4（平台上傳）
  ├─ 圖片素材（素材庫）
  └─ HTML 版（Web 備用）
```

## 架構決策紀錄

### 決策①：模組解耦

**決策**：各功能模組獨立開發，不綁定此流水線。此專案只做兩件事：索引（哪些模組、照什麼順序）與驗證（每個節點的輸出怎麼確認是對的）。

**動機**：避免重複造輪子；單一功能（如「圖片 → Figma 版型生成」）可獨立用於平面設計等其他場景，不應只活在影片製作流程裡。

### 決策②：半自動化優於全自動

**決策**：全自動目前不可行，中間需要多個人工審核節點。

**動機**：不同客戶有不同需求，AI 在完全理解使用者意圖之前無法保證一致性；業界專業使用者（包含 HTML 開發者）也普遍保有半自動設計，在關鍵節點確保產出方向正確。

### 決策③：工具選型

**決策**：Figma 作為模板設計層（非 Adobe）；Premiere 作為影片組裝層；HTML 與 AE 並存（分工邊界待定）。

**動機**：
- Figma API 比 Adobe 家族更穩定、更友善，適合 AI 操作
- Figma → Illustrator 插件解決了 Figma 到 Adobe 工作流程的橋接問題
- Adobe 全家桶的核心價值在 Premiere 的素材組裝能力，而非 PS/AI 的 API

## 核心流程決策（2026-06-10 確認）

### 圖片 → Figma → HTML 三步流程

```
[參考圖片輸入]
        ↓
[AI 分析圖層結構，在 Figma 重建版型]
        ↓ ← ✋ 人工審核：圖層是否正確？去背素材是否需要補充？
           （必要時使用者直接在 Figma 調整後回傳檔案）
        ↓
[確認後輸出至 HTML，依使用者需求替換元素內容]
        ↓
[最終可用版型]
```

**選擇這個流程的原因**：
- AI 的不足處（元素位置偏差、去背素材缺失）都是人可以直接在 Figma 修正的範圍
- 修正完的 Figma 檔案就是設計師視角的「可用版型」
- HTML 端只需依圖層資訊對應元素進行替換，不需重新解讀設計

## AI 圖層能力驗證結論（實作測試 2026-06-10）

透過四張參考圖片的 HTML 實作驗證：

| 設計類型 | 圖層分離 | 說明 |
|---|---|---|
| 純文字排版（BRAND VALUE） | ✅ 正確 | CSS Grid，零圖片依賴 |
| 全滿背景照 + 文字疊加（Rule of Thirds） | ✅ 正確 | 背景照 + overlay，純 CSS |
| 文字鏤空透圖（URBAN） | ✅ 正確 | `background-clip: text` 技巧 |
| 兩欄分割 + 浮動物件（EMBER STUDIO） | ⚠️ 架構對，石頭需去背素材 | 版型結構正確，素材需上游處理 |
| 結構清單 + 浮動產品（CODE:7） | ✅ 正確 | 清單版型無問題，產品需去背素材 |
| 複雜照片疊加（TERRA cotta） | ❌ 未採用 | 依賴特定建築照，CSS 無法模擬 |

**結論**：AI 對圖層分離的理解基本正確，人工審核的主要價值在於確認去背素材是否到位、以及調整元素位置的精確度。

## ★ 已知限制：AI 的群組問題（重要）

**問題描述**：
AI 輸出 Figma 時，傾向把每一行/每一句文字當作**獨立的文字元素**，而非一個含換行的文字框。

**舉例（Ref1 左下角說明文字）**：
```
AI 的輸出（錯誤）：         正確的 Figma 結構：
  Text: "Workspace..."       Text Frame（一個元素）:
  Text: "Business..."          "Workspace atmosphere..."
  Text: "Office..."            換行
  （三個獨立元素）             "Business center exterior..."
                               換行
                               "Office interior..."
```

**為什麼這是嚴重問題**：
- 設計師選取時必須同時管理多個元素，無法直接編輯整塊文字
- 間距不再由字型 line-height 控制，而是多個元素的相對位置（難以整體調整）
- 這是目前主流 AI 生成設計檔案的共同問題，也是設計師無法直接使用 AI 輸出檔案的主因之一

**處理方式**：
- 這是人工介入節點的主要工作項目之一
- 輸出 Figma 後，使用者在 Figma 內合併相關文字元素、建立正確的群組結構
- **這也是整個 Pipeline 強調「半自動 + 人工審核」而非全自動的核心原因**
