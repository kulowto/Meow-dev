# 二分法查詢（Binary Search）

- 分類：搜尋演算法
- 對應 C#：`Array.BinarySearch` / `List<T>.BinarySearch`（內建方法，這裡先理解原理，之後可以自己手刻）

> 複習時先看 Q，自己講一遍答案，再點開 `<details>` 對答案。答錯或講不出來的，去下面「完整筆記」補。
> 跟 [`map`](map.md) 的紅黑樹是同一種「每步排除一半」精神的兩種實作，建議一起複習對照。

## 自我測驗

<details>
<summary>Q1. 這是什麼？使用前提是什麼？</summary>

A1. 在**已排序**的**連續陣列**上，每次比較中間元素，依大小關係砍半縮小搜尋範圍。前提有兩個：資料必須先排序好，而且要用陣列這種支援 O(1) index 隨機存取的結構——`list`（連結串列）就算排序好也不能用二分法有效率地查，因為沒有 O(1) 隨機存取。

</details>

<details>
<summary>Q2. 核心邏輯怎麼寫？</summary>

A2.
```cpp
int low = 0, high = n - 1;
while (low <= high) {
    int mid = low + (high - low) / 2;   // 避免 low+high 溢位
    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) low = mid + 1;
    else high = mid - 1;
}
return -1; // 找不到
```

</details>

<details>
<summary>Q3. 常見的坑是什麼？</summary>

A3.
1. 資料**沒排序**就用二分法，結果完全不可靠——這是最容易忘記檢查的前提
2. `mid = (low + high) / 2` 在 `low`、`high` 都很大時可能整數溢位，寫成 `low + (high - low) / 2` 比較安全
3. 排序陣列的**插入/刪除代價是 O(n)**：為了維持連續記憶體 + 排序，插入點之後的所有元素都要往後搬一格。這是它跟 `map`（紅黑樹）最大的差異來源

</details>

<details>
<summary>Q4. 時間/空間複雜度？</summary>

A4. 查詢 O(log n)，空間 O(1)（不需要額外空間）。但如果資料本身需要頻繁新增/刪除，插入/刪除是 O(n)，這點常被忽略——二分法查詢快，不代表整個資料結構的維護成本低。

</details>

## 完整筆記

陣列在記憶體裡是**連續**的一塊空間，可以用 index 直接算出任何位置（`arr[i]`），這是 O(1) 隨機存取。二分法就是靠這點：算中間 index、比大小、砍半，全程是「算數學算出位置」，不是沿著什麼路徑走訪。

### 為什麼插入很貴——生活比喻

- **印刷字典**：所有字印在連續紙頁上，依字母排序。查字很快（一頁頁對半翻），但出版後想「插入」一個新單字到中間，沒辦法只改一頁——後面所有頁碼、排版都要重印。這是陣列插入昂貴的現實版本
- **圖書館舊式卡片目錄抽屜**：每一筆資料是一張獨立卡片，可以自由抽換位置。新書進來，找到該插入的位置塞進去就好，不用把後面卡片全部往後挪——因為卡片本來就各自獨立，不要求物理連續。這對應的就是 `map`（紅黑樹）用指標連接節點的精神

### 跟 map（紅黑樹）的關係

兩者查詢精神都是「每一步排除一半範圍」，複雜度同為 O(log n)，但陣列犧牲了插入/刪除的彈性換取更單純的實作跟更好的 cache 局部性；樹用指標換取插入/刪除的低成本。哪個情境用哪個，見 `map.md` 裡的對照表。
