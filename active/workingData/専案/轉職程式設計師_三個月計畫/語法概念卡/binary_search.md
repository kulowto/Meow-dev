# 二分法查詢（Binary Search）

- 分類：搜尋演算法
- 對應 C#：`Array.BinarySearch` / `List<T>.BinarySearch`（內建方法，這裡先理解原理，之後可以自己手刻）

> 複習時先看 Q，自己講一遍答案，再點開 `<details>` 對答案。答錯或講不出來的，去下面「完整筆記」補。
> 跟 [`map`](map.md) 的紅黑樹是同一種「每步排除一半」精神的兩種實作，建議一起複習對照。

## 自我測驗

<details>
<summary>Q1. 這是什麼？使用前提是什麼？</summary>

A1. 在**已排序**的**連續陣列**上，每次比較中間元素，依大小關係砍半縮小搜尋範圍。前提有兩個：資料必須先排序好，而且要用陣列這種支援 O(1) index 隨機存取的結構——`list`（連結串列）就算排序好也不能用二分法有效率地查，因為沒有 O(1) 隨機存取。

</details>

<details>
<summary>Q2. 核心邏輯怎麼寫？</summary>

A2.
```cpp
int low = 0, high = n - 1;
while (low <= high) {
    int mid = low + (high - low) / 2;   // 避免 low+high 溢位
    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) low = mid + 1;
    else high = mid - 1;
}
return -1; // 找不到
```

</details>

<details>
<summary>Q3. 常見的坑是什麼？</summary>

A3.
1. 資料**沒排序**就用二分法，結果完全不可靠——這是最容易忘記檢查的前提
2. `mid = (low + high) / 2` 在 `low`、`high` 都很大時可能整數溢位，寫成 `low + (high - low) / 2` 比較安全
3. 排序陣列的**插入/刪除代價是 O(n)**：為了維持連續記憶體 + 排序，插入點之後的所有元素都要往後搬一格。這是它跟 `map`（紅黑樹）最大的差異來源

</details>

<details>
<summary>Q5. 「找第一個 True」變體：跟一般找目標值的二分法差在哪？</summary>

A4. 不是在數字陣列裡找特定值，是在一個**單調的布林序列**（一串 `false` 接一串 `true`）裡找第一個 `true` 出現的位置，判斷條件從「數值比較」換成「呼叫 API 或函式拿布林結果」，核心的縮小範圍邏輯完全一樣。

固定角色設計：`head` 永遠代表「確定是 `false`」的位置，`tail` 永遠代表「確定是 `true`」的位置，`head`、`tail` 相鄰（`head+1==tail`）時，答案固定是 `tail`——不要用「往左搜尋回傳 head、往右搜尋回傳 tail」這種依賴搜尋方向的規則，容易在頭尾相鄰時回傳到錯誤的一邊。

**初始值要注意邊界**：如果合法範圍是 `1` 到 `n`，`head` 不能直接設成 `1`（因為答案可能剛好是 `1`，這樣 `head=1` 從一開始就不符合「確定是 false」的性質）。要設成 `0`（範圍外、保證是 false 的虛擬位置），才能保證這個性質從一開始就成立（First Bad Version 這題踩過這個坑）。

</details>

<details>
<summary>Q4. 時間/空間複雜度？</summary>

A4. 查詢 O(log n)，空間 O(1)（不需要額外空間）。但如果資料本身需要頻繁新增/刪除，插入/刪除是 O(n)，這點常被忽略——二分法查詢快，不代表整個資料結構的維護成本低。

</details>

## 完整筆記

陣列在記憶體裡是**連續**的一塊空間，可以用 index 直接算出任何位置（O(1) 隨機存取）。二分法靠這點：算中間 index、比大小、砍半，全程是「算數學算出位置」，不是沿路徑走訪。

**生活比喻**：印刷字典——依字母排序印在連續紙頁上，查字很快（一頁頁對半翻），但想「插入」一個新單字到中間，後面所有頁碼排版都要重印（= 陣列插入 O(n）。對照 `map`（紅黑樹）像圖書館卡片抽屜，每張卡片獨立、找位置塞進去就好。

跟 [`map`](map.md)（紅黑樹）的關係：兩者查詢都是「每步排除一半」O(log n)，差在陣列犧牲插入/刪除彈性換更好的 cache 局部性；樹用指標換插入/刪除的低成本。對照表見 `map.md`。
