# 網格走訪：方向增量陣列（dx/dy）

- 分類：解題技巧（樣板寫法，不綁定特定容器）
- 對應 C#：無直接語法對應，這是程式碼組織手法，任何語言都能用同樣的概念

> 複習時先看 Q，自己講一遍答案，再點開 `<details>` 對答案。
> 這是處理「網格 / 二維陣列，要往多個方向擴散」類題目的固定套路。

## 自我測驗

<details>
<summary>Q1. 這是什麼？什麼情境下會想到用它？</summary>

A1. 網格類題目常常要往上下左右（甚至八個方向含對角線）擴散處理。如果四個方向各寫一次幾乎重複的程式碼，會冗長又難維護。改成把每個方向的「行、列」變化量存成兩個陣列，用迴圈跑過所有方向，四個方向共用同一段邏輯。看到「網格、多方向擴散、上下左右」這類題目，直接想到這個套路。

</details>

<details>
<summary>Q2. 核心語法怎麼寫？</summary>

A2.
```cpp
int dx[] = {-1, 1, 0, 0};   // 上、下、左、右 各自的「行」變化量
int dy[] = {0, 0, -1, 1};   // 上、下、左、右 各自的「列」變化量

for (int d = 0; d < 4; d++) {
    int newRow = row + dx[d];
    int newCol = col + dy[d];
    // 對 (newRow, newCol) 做處理
}
```
`dx[d]`、`dy[d]` 兩個陣列的**索引要一一對應**——`dx[0]`、`dy[0]` 合起來才是「上」這一個方向的完整位移量，不能只看其中一個陣列。

</details>

<details>
<summary>Q3. 常見的坑是什麼？</summary>

A3.
1. **一定要先做邊界檢查，才能存取新座標**：`newRow`、`newCol` 算出來後，可能超出網格範圍（小於 0，或 ≥ 行數/列數）。網格不像樹狀結構有 `nullptr` 天然擋住越界，直接存取 `grid[newRow][newCol]` 會直接出範圍錯誤，邊界檢查必須寫在存取之前。
2. `dx`、`dy` 兩個陣列的順序要保持一致（例如都照「上、下、左、右」的順序排），不能其中一個陣列重排了、另一個沒跟著動，不然方向會對不上。
3. 需要八個方向（含對角線）時，只要在 `dx`、`dy` 各加 4 組值，迴圈跟主邏輯完全不用改，這是這個套路可擴充的地方。

</details>

## 完整筆記

跟樹狀結構的走訪（例如 Invert Binary Tree 用遞迴呼叫 `invert(node->left)`、`invert(node->right)`）比較：樹的「往下一層」用指標天然表達、越界用 `nullptr` 天然擋住；網格沒有這種天然機制，方向要自己用 `dx`/`dy` 明確定義，邊界也要自己明確檢查。兩者都可以搭配遞迴（DFS）或 Queue（BFS）做擴散式走訪，差別只在於「如何算出下一個要處理的位置」這一步。
