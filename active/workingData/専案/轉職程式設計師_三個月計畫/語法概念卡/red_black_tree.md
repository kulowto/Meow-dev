# 紅黑樹（Red-Black Tree）

- 分類：資料結構（自平衡二元搜尋樹）
- 對應 C#：`SortedDictionary`/`SortedSet` 底層實作原理相同（C# 官方沒有明確保證是紅黑樹，但概念對應）

## 自我測驗

<details>
<summary>Q1. 這是什麼？為什麼需要「平衡」？</summary>

A1. 一種**自平衡二元搜尋樹**（self-balancing BST）。普通 BST 如果不做任何平衡處理，最壞情況（例如依序插入 1,2,3,4,5）會**退化成一條鏈**，查詢變成 O(n)，完全失去樹狀結構原本想要的 O(log n) 優勢。紅黑樹靠幫每個節點加一個「顏色」屬性（紅/黑）加上幾條規則，強制樹的高度維持在 O(log n)，不管怎麼插入刪除都不會退化。

</details>

<details>
<summary>Q2. 節點（Node）本身包含什麼？</summary>

A2. 比普通 BST 節點多一個欄位：
- `value`：儲存的資料
- `left` / `right` 指標：指向左右子樹
- `parent` 指標：指向父節點（方便平衡調整時往上找）
- `color`：紅或黑

</details>

<details>
<summary>Q3. 平衡規則是什麼？（不用背細節，知道大方向就好）</summary>

A3. 經典規則包括：根節點必須是黑的、紅色節點的子節點不能也是紅的（不能兩個紅色相連）、從任一節點走到它所有後代 leaf 的路徑上，黑色節點數量都要相同。插入/刪除違反規則時，靠**旋轉（rotation）**跟**變色**調整回平衡。

刷題階段**不需要背這些規則、也不用自己實作**，只要知道：它保證 insert / delete / search 在任何情況下都是 O(log n)，這就是它存在的意義。

</details>

<details>
<summary>Q4. 時間/空間複雜度？</summary>

A4. 查詢/插入/刪除都是 **O(log n)**——關鍵是「最壞情況也保證這個複雜度」，不會像普通未平衡的 BST 退化成 O(n)。空間 O(n)。

</details>

## 完整筆記

C++ STL 的 `map`、`set` 底層都是紅黑樹實作。

**為什麼 STL 選紅黑樹，不是其他平衡樹（例如 AVL 樹）**：AVL 樹對「平衡」的要求更嚴格（左右子樹高度差最多 1），查詢稍微快一點點，但插入/刪除時為了維持這麼嚴格的平衡，需要做更多次旋轉。紅黑樹的平衡要求比較寬鬆，插入/刪除的旋轉次數更少，更適合「寫入頻繁」的場景——這也是為什麼通用型容器（`map`/`set`）選紅黑樹而不是 AVL 樹。這段背景知識，之後不用深究，知道「有取捨」就好。
