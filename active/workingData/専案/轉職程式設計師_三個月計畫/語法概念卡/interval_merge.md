# 區間合併（Interval Merge）：三態互斥分類

- 分類：解題思維框架（單一掃描 + 狀態分類）
- 對應 C#：無直接語法對應，是思考套路

> 複習時先看 Q，自己講一遍答案，再點開 `<details>` 對答案。答錯或講不出來的，去下面「完整筆記」補。
> 跟 [`order_vs_value.md`](order_vs_value.md) 是同一種精神：輸入本身已排序時，優先用單一掃描延續順序，不要另外建結構或找索引修補。

## 自我測驗

<details>
<summary>Q1. 遇到「排序好、彼此不重疊的區間陣列，插入一個新區間並合併重疊部分」這種題目，核心思路是什麼？</summary>

A1. **由左到右單一掃描一次**，把每個既有區間分成三種**互斥**的狀態，依序判斷：

1. **完全在新區間左邊，不重疊**（`intv[i].end < nIntv.start`）→ 原封不動放進答案
2. **跟新區間有重疊**（`nIntv.start <= intv[i].end && nIntv.end >= intv[i].start`，兩個方向都要成立）→ 不放進答案，改成**擴大新區間本身**：`nIntv.start = min(nIntv.start, intv[i].start)`，`nIntv.end = max(nIntv.end, intv[i].end)`，繼續下一輪
3. **完全在新區間右邊，不重疊**（前兩者都不成立）→ 這時候（可能已經被擴大過的）`nIntv` 該放進答案了（只做一次），然後這個區間也放進答案

不需要「先找插入位置索引、分別處理頭尾端點、再刪除中間區間」這種修補式做法，一次掃描邊判斷邊處理即可。

</details>

<details>
<summary>Q2. 「兩個區間有重疊」的判斷式，容易漏掉什麼？</summary>

A2. 必須**同時滿足兩個方向**才算重疊：`A.start <= B.end && B.start <= A.end`。只檢查其中一個方向（例如只看「A 的結尾有沒有超過 B 的開頭」）會漏掉「A 完全在 B 右邊、中間有空隙」這種其實不重疊的情況，誤判成重疊。

</details>

<details>
<summary>Q3. 為什麼三個狀態一定要用 `if/else if/else`，不能用三個獨立的 `if`？</summary>

A3. 如果三個判斷式各自獨立寫成三個 `if`，同一輪可能會有不只一個條件同時成立（例如「合併」條件成立的那一輪，「該放進答案」的條件也剛好成立），導致重複推播或推播到還沒合併完的舊值。用 `if/else if/else` 讓解釋器一輪只會進入其中一個分支，保證三個狀態互斥。**一組資料邏輯上該分成互斥的幾種狀態時，都要優先想到用 `else if` 串起來，而不是各自獨立判斷**，這個原則不只適用於區間題目。

</details>

<details>
<summary>Q4. 迴圈跑完之後，新區間還沒被放進答案怎麼辦？</summary>

A4. 如果新區間跟最後幾個既有區間一路合併下去、從來沒有進入「右邊不重疊」的分支（例如新區間比所有既有區間都晚結束），迴圈跑完 `nIntv` 會被漏掉。用一個布林旗標（例如 `trigger`）記錄「有沒有推播過」，迴圈外再檢查一次：還沒推播過就補推一次。這跟 Add Binary 的「把收尾動作塞進迴圈條件本身」是同一類「迴圈跑完可能還有一個收尾動作」的問題，只是這裡的收尾動作（只推播一次）用布林旗標 + 迴圈外檢查處理更直覺，不一定都要塞進迴圈條件本身。

</details>

<details>
<summary>Q5. 迴圈跑完才推播的寫法（用布林旗標），能不能更省？</summary>

A5. 可以，利用「輸入已排序」這個性質提早 `break`：一旦確認某個區間「完全在 `nIntv` 右邊、不重疊」（狀態 3），因為排序保證了後面的區間只會更右邊，**後面所有區間都不可能再跟 `nIntv` 重疊**，可以直接 `break`，不用再讓剩下的元素逐一跑過三個條件判斷。

```cpp
int i = 0;
for(; i < intv.size(); i++){
    if(nIntv[0] > intv[i][1]){
        res.push_back(intv[i]);
    } else if(nIntv[0] <= intv[i][1] && nIntv[1] >= intv[i][0]){
        nIntv[0] = min(intv[i][0], nIntv[0]);
        nIntv[1] = max(intv[i][1], nIntv[1]);
    } else {
        break;   // 排序保證後面不會再重疊，停止判斷
    }
}

res.push_back(nIntv);   // 不管是自然跑完還是 break，這裡只推播一次

for(; i < intv.size(); i++){
    res.push_back(intv[i]);   // 剩下原封不動複製（包含觸發 break 的那個）
}
```

讓 `i` 這個變數在兩個迴圈間共用，第一個迴圈結束時 `i` 停在哪裡，第二個迴圈就從那裡接著複製，連判斷 `trigger` 的布林旗標都不需要了。

**這不是判題機雜訊，是真正的架構層面優化**：兩種寫法 Big-O 時間複雜度都是 O(n)（每個元素只看過一次），差別在於「用布林旗標」的版本讓每個剩餘元素都跑過完整的三個條件判斷，「提早 break」的版本則讓剩餘元素直接跳過所有判斷、單純複製——**當資料的某個性質（這裡是排序）能保證『後面不可能再發生你在意的情況』時，可以提早停止判斷，把後面的工作簡化成單純複製**，這個技巧不只適用於區間題目，任何走訪已排序資料、確認某個條件後就不會反悔的情境都能用。

</details>

## 完整筆記

這個套路本質上是「順序重要」（見 `order_vs_value.md`）的一種具體應用：輸入已經排序好，不需要重新排序或建立額外結構，單一掃描、邊走邊判斷狀態即可完成，時間複雜度 O(n)、空間複雜度 O(n)（輸出陣列本身）。

跟「找插入索引 + 分別處理頭尾 + 刪除中間區間」這種修補式做法比，三態分類法不需要處理邊界索引（例如插入點在最前面時 `i-1=-1` 這種情況），因為「完全在左邊」「完全在右邊」這兩個狀態本身就自然涵蓋了所有邊界情況。
