# 刷題詳細記錄使用規範

> 使用者貼 LeetCode 解法要求 review，或要求記錄複習結果時，AI 依此規範處理。

## 分工邊界

- **Google Sheet**（見 `Sheet匯入設定說明.md`）：量化 SRS 排程資料（EF / n / Interval / 狀態），AI 不負責維護，使用者自行在 Sheet 操作。
- **`刷題詳細記錄/`**：質化深度分析，AI 負責產出與累加內容。兩者用 LeetCode 題號互相對照，不重複記錄對方的欄位。

## Review 三維度（固定）

使用者每次貼程式碼要 review 時，一律照以下三個維度評，不額外加維度、不省略：

1. **語法概念**：這段用到哪些 C++ 特有語法／組合方式，值不值得注意（C# 背景轉 C++，可對照 C# 講差異）
2. **邏輯與複雜度**：目前寫法的時間/空間複雜度，是否過於複雜、有沒有更精簡寫法
3. **演算法 / 資料結構盲點**：有沒有更適合的工具（雙指標、單調棧、Hash、Union-Find 等）當下沒想到

回覆風格：直接指出好壞與進步空間，不用寒暄鋪陳。

## 「過」的判定標準（使用者定義）

- 使用者的標準：必須**獨立**在**限時內、一次通過**、且能直覺想出思路，才算「過」（狀態＝限時內完成）
- 若使用者是透過向 AI 提問、討論才想出思路或寫出解法，即使最終程式碼正確能跑，**也不算過**，狀態要標「寫不出來」（如果連思路都是靠討論才有）或「有Bug」（如果思路自己有、但寫的過程中卡在語法/實作錯誤靠討論排除）
- AI 建議狀態欄位時要照這個標準判斷，不要因為「程式碼最後是對的」就自動標成「限時內完成」

## 檔案處理規則

- 範本：`刷題詳細記錄/_範本.md`
- 檔名：`[題號]_題名.md`
- **同一題永遠用同一個檔案**，每次複習是新增一段（`## 複習 #N — 日期`）往下累加，不開新檔、不覆寫舊段落
- 每段結尾一定要填「跟上次相比」——第一次複習留空，第二次起要明確寫「上次的盲點這次解決了嗎」+「新出現的問題」
- 若使用者貼的是全新題目（該題號檔案不存在），複製範本建立新檔案

## 跨題目盲點彙總規則

- 檔案：`跨題目盲點彙總.md`
- **只登記重複出現的盲點**，單題特例不登記。判斷標準：同一類盲點在不同題目出現第 2 次以上，才補一行
- 三個維度分開登記，對應 Review 三維度的分類
- 每次 review 完，AI 主動比對這次的盲點跟彙總表是否重複，重複才動手寫入，不用每次都問使用者

## 語法概念卡規則（`語法概念卡/`）

- 用途：記錄「思路跟用法」本身（例如某個 STL 容器、演算法技巧），跟 `刷題詳細記錄/` 記的「單題解法」不同層級——概念卡是可跨題複用的知識點，不綁定單一題目
- **觸發時機**：使用者在 review 或深聊時針對某個語法/容器/技巧要求「深入問」「詳細解釋」，且該概念值得未來複習，就主動問使用者要不要存成概念卡；使用者沒特別要求記錄的技術解釋，不主動存
- 範本：`語法概念卡/_範本.md`，檔名用概念本身（例如 `unordered_map.md`）
- 格式核心：用 `<details><summary>` 做「先想再看答案」的自我測驗區塊（Q1 用途、Q2 核心操作、Q3 常見坑、Q4 複雜度），下方「完整筆記」放對答案用的完整內容
- 每次這個概念在新題目用到，都要回來這張卡的「出現過的題目」表格補一行，不用整張重寫
- 同一概念已有卡片時，新內容用**補充**方式加進對應 Q&A 或完整筆記，不重複建新檔

## 新建 / 刪除檔案時

依 Meow-agent CLAUDE.md 規定，`刷題詳細記錄/` 或本專案資料夾下新增、刪除、改名任何檔案時，必須同步更新 `../../MENU.md` 對應行。
