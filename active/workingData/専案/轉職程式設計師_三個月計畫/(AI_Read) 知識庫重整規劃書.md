# 知識庫重整規劃書

> 對象：接手執行「刷題知識庫壓縮與重整」的 AI。
> 目的：讓你不需要重新推敲使用者的分類邏輯，直接照這份規劃書思考與執行。
> 建立日期：2026-09-10（累積刷題數 32 題時提出）

---

## 一、為什麼要做這次重整

刷題累積到 32 題後，`語法概念卡/`（21 張）跟 `刷題詳細記錄/`（32 份）都長大了，使用者回報的核心摩擦是：

> 「使用上沒太多問題，主要是要調用一些之前的資料時，會有點繁瑣。希望把之前的內容進行壓縮並重新整理一次，方便之後讀取跟使用。同時有些概念卡跟題目，彼此會有連結性，這些也想處理一下。」

翻譯成可執行的問題：

1. **沒有導覽層**——要找「某個主題有沒有卡」「某類錯誤出現在哪幾題」時，只能逐一開檔猜，慢
2. **有重疊的卡片**——例如 `map.md` 跟 `red_black_tree.md` 都在講紅黑樹原理，`unordered_set.md` 幾乎就是「沒有 value 的 `unordered_map`」
3. **卡片內容有冗長處**——某些「完整筆記」重複了「自我測驗 Q&A」已經講過的東西
4. **交叉連結是單向、零散的**——A 卡連到 B 卡，B 卡不一定連回 A；卡片的「出現過的題目」跟題目記錄的「相關概念卡」不一定對齊

## 二、使用者的分類邏輯（重整的核心依據）

使用者把知識分成兩個軸，**這是整個導覽結構的骨架，不要自己另創分類**：

### 軸一：方法論（「遇到題目，該往哪個方向想」）

重點在「**什麼場景用什麼資料結構／演算法**」。這一軸的卡片是「拿到新題目時的判斷入口」。

| 子類 | 卡片 | 說明 |
|------|------|------|
| **決策入口**（最優先讀） | `order_vs_value`、`container_selection` | 「答案跟順序有關嗎」「該用哪個容器」——所有題目先從這兩張過濾方向 |
| 演算法思維 | `recursion`、`dynamic_programming`、`bfs`、`binary_search` | 遞迴 / DP / 廣度優先 / 二分 |
| 雙指標家族 | `sliding_window`、`two_pointers_sum`、`floyd_cycle` | 三種不同應用場景的雙指標 |
| 掃描 + 狀態分類 | `interval_merge`、`digit_carry_addition`、`grid_traversal` | 單次線性掃描搭配狀態機 / 進位 / 方向增量 |

### 軸二：語法（「這個東西具體怎麼用」）

重點在「**這個容器／語法的 API 怎麼用**」以及「**同類的多個選項要怎麼挑**」。

| 子類 | 卡片 | 說明 |
|------|------|------|
| 容器 API + 選擇邏輯 | `vector`、`unordered_map`（含 set）、`map`（含紅黑樹原理）、`stack` | 每張講具體用法 + 常見坑；「怎麼在多個容器間挑」的邏輯集中在 `container_selection`（屬軸一決策入口，但兩軸都會連過去） |
| C++ 語法 | `class_basics`、`range_based_for` | 物件導向基礎 / range-based for |

### 軸三（附屬）：錯誤模式

不是新的一組卡，是既有的 `跨題目盲點彙總.md`，維持它原本的三維度（語法概念／邏輯與複雜度／演算法資料結構盲點）。刷題導覽的「犯過的錯誤」欄會連回這裡。**登記標準不變**：只登記「同一類在不同題目出現第 2 次以上」的盲點，單題特例不登記（見 `(AI_Read) 刷題詳細記錄使用規範.md` §跨題目盲點彙總規則）。

## 三、要產出/修改的東西（執行清單）

### 3-1 合併重疊卡片（2 組）

| 動作 | 細節 |
|------|------|
| `red_black_tree.md` → 併入 `map.md` | 兩張都在講紅黑樹原理、都還沒被任何題目用到（「出現過的題目」皆空）。把紅黑樹的「為什麼要平衡 / 節點結構 / 平衡規則大方向 / 為什麼 STL 選紅黑樹不選 AVL」收進 `map.md` 的「底層機制」章節（可用 `<details>` 摺疊，保持 `map.md` 主體精簡）。刪除 `red_black_tree.md`。更新所有連到 `red_black_tree.md` 的卡片（`linked_list.md`、`order_vs_value.md`、`recursion.md`、`container_selection.md`、`map.md` 自己）改指向 `map.md` 或該章節錨點 |
| `unordered_set.md` → 併入 `unordered_map.md` | `unordered_set` 就是「沒有 value 的 `unordered_map`」，本來就大量互連。變成 `unordered_map.md` 的一個章節（**保留** 217 Contains Duplicate 的題目紀錄、以及「Big-O 好但實測不一定快」的註記）。刪除 `unordered_set.md`。更新 `container_selection.md`、`vector.md`（若有連）等處的連結 |

**不合併**：`floyd_cycle.md` 維持獨立（它是「快慢指標」這個特定技巧，跟 `sliding_window`／`two_pointers_sum` 平行，只是剛好都用在鏈結串列環偵測時會連到 `linked_list.md`）。

### 3-2 精簡卡片內容

**鐵則：自我測驗的 `<details>` Q&A 全部保留，一個字都不刪**——那是複習的核心。只精簡「完整筆記」裡「跟 Q&A 重複」或「背景知識講太細」的部分。

重點對象：

- `unordered_map.md`：Q1–Q7 已經很多，檢查有無可合併的 Q（例如 `count` vs `find` 的討論散在多個 Q）；三個生活比喻（健身房置物櫃 / 超商取貨 / 停車場）收斂成一句話帶過；「命名由來」章節精簡
- `binary_search.md`、`map.md`：完整筆記裡的記憶體佈局比較、生活比喻，檢查是否過長
- 其他卡片：逐張快速看一遍，「完整筆記」超過 Q&A 總長度的，優先檢視

判斷準則：**這段文字拿掉之後，使用者複習時會不會少掉「答對 Q 需要的資訊」？** 會 → 留（或移進對應的 Q 的 A 裡）；不會（只是補充讀物）→ 刪或濃縮成一句。

### 3-3 建立兩份導覽索引

**`語法概念卡/導覽.md`**：

- 開頭一句話說明「這是索引，找卡片先看這裡，不要逐一開檔」
- 按「二、使用者的分類邏輯」的軸一 / 軸二 / 子類分組
- 每張卡列：卡名（連結）＋**一句話**摘要（≤ 25 字）＋主要關聯卡片
- 附一個「決策流程」小段：拿到新題目 →（1）先讀 `order_vs_value`／`container_selection` 判斷方向 →（2）確定演算法方向後查對應方法論卡 →（3）實作卡關查語法卡 →（4）收尾比對 `跨題目盲點彙總`

**`刷題詳細記錄/導覽.md`**：

- 表格欄位：`題號｜LC#｜題名｜Level｜狀態｜方法論重點｜語法重點｜犯過的錯誤`
- 依「題號」（內部序號，非 LeetCode 題號）排序
- 「方法論重點」「語法重點」各填 1–2 個關鍵詞（對應到概念卡名）
- 「犯過的錯誤」填錯誤類型關鍵詞，連到 `跨題目盲點彙總.md` 對應維度
- 「狀態」用既有標準：限時內完成 / 有Bug / 超時 / 寫不出來
- 表格下方補一句：「想補強某一類 → 用這個表篩選同性質題目重寫」

### 3-4 雙向連結稽核

- 掃一遍所有卡片的 `[`xxx.md`]` 連結：A 連到 B、B 的內容跟 A 相關但沒回連 → 補上（不合理的不用硬連）
- 逐題比對：每張卡的「出現過的題目」表 ↔ 每份題目記錄開頭的「相關概念卡」，兩邊對齊補齊缺漏
- 合併卡片後，舊卡名的所有連結都要更新，不能留死連結

### 3-5 更新 skill.md（`~/.claude/commands/leetcode-tutor.md` 同步）

在「已知路徑」清單補兩行：

| 用途 | 路徑 |
|------|------|
| 概念卡導覽（找卡片先讀這份，不要逐一開檔） | `.../語法概念卡/導覽.md` |
| 刷題記錄導覽（掃過去題目、篩選同類錯誤補強用） | `.../刷題詳細記錄/導覽.md` |

並在「讀取前置」段落補一句：**查閱過去的概念卡或題目記錄時，先讀對應的導覽檔定位，不要逐一開檔猜。**

### 3-6 補記第 31 題（102 Binary Tree Level Order Traversal）的 BFS 版本

- 使用者用 DFS + 深度參數解過一次（狀態：有Bug，90 分），事後又寫了 BFS（queue + 每層開始前鎖定 `queue.size()`）版本，一次寫對
- 在 `31_BinaryTreeLevelOrderTraversal.md` 現有那段「複習 #1」**下方補一小節**「其他解法：BFS 版本」，貼 BFS 程式碼 + 簡述「用 `queue.size()` 鎖定每層節點數」的關鍵，並補充 DFS vs BFS 的實作難度對照（BFS 概念天生契合、一次寫對；DFS 要多帶深度參數、`depth++` 副作用、`while` 補 `rtn` 大小兩個坑）
- 不另開複習段（不是新的一次獨立作答，是同一題的第二種解法）
- 對應更新 `bfs.md` 的「出現過的題目」表補 102

### 3-7 更新 MENU.md

依 `Meow-Framework/CLAUDE.md` 規定，`workingData` 下新增/刪除檔案要同步更新 `../../MENU.md`。這次新增 `(AI_Read) 知識庫重整規劃書.md`、`語法概念卡/導覽.md`、`刷題詳細記錄/導覽.md`，刪除 `red_black_tree.md`、`unordered_set.md`。

## 四、執行順序建議

1. **先做 3-6（補第 31 題 BFS）**——獨立、小、不影響其他
2. **3-1 合併卡片**——先合併，因為 3-3 導覽、3-4 連結稽核都依賴最終的卡片清單
3. **3-4 雙向連結稽核**——合併後立刻做，把死連結、缺漏補齊
4. **3-2 精簡內容**——逐張過
5. **3-3 建立兩份導覽**——內容定案後才寫索引
6. **3-5 更新 skill.md**
7. **3-7 更新 MENU.md**
8. 最後 commit + push（Meow-Dev 放知識庫、Meow-agent 放 skill.md 改動）

## 六、給執行 AI 的提醒

- **不要動題目記錄的「複習 #N」內容**（那是歷史，只能往下累加）——這次只在第 31 題補一個「其他解法」小節，其他題目記錄不動
- **不要改跨題目盲點彙總的登記標準**——維持「第 2 次以上才登記」
- 精簡時如果拿不準某段要不要刪，**留著**——寧可稍微冗長，不要刪掉複習需要的資訊
- 合併卡片時，被合併方的「出現過的題目」紀錄一定要搬到主卡，不能遺失
