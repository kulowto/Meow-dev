### 我的解法

```cpp
class Solution {
public:
    int climbStairs(int n) {

        if(n < 0){
            return -1; // ERROR CODE
        }

        if( n >= 2 ){

            int p1 = 1;
            int p2 = 1;
            int sum = 0;

            for (int i = 2 ; i <= n ; i++){
                sum = p1 + p2;
                p2 = p1;
                p1 = sum;
            }

            return sum;

        }

        return 1; // n = 0 & 1

    }
};
```

- 時間複雜度：O(n)
- 空間複雜度：**O(1)**（用兩個滾動變數取代整個陣列，是這題的最優解）

### 解題過程

#### 一開始想用排列組合硬算，繞了遠路

最初想用「把幾個 1 併成 2」的組合數學去解，算到一半發現要考慮重複排序，越算越複雜。討論後改成思考「最後一步是怎麼走的」——最後一步不是走 1 階（來自 `n-1`）就是走 2 階（來自 `n-2`），兩者互斥，得出遞迴關係式 `ways(n) = ways(n-1) + ways(n-2)`，並正確設出兩個 base case：`ways(0)=1`、`ways(1)=1`（避免遞迴算到 `ways(-1)` 這種不合理的負數）。

#### 記憶化容器選擇的坑，跟 Ransom Note 是同一種

一開始提出用 `pair<int,int>` 存「n 對應答案」，被指出這跟 Ransom Note 犯的是同一種錯——`pair` 只能裝一組資料，這題需要同時記住 `n=0` 到 `n=45` 這麼多筆答案，應該用容器（陣列/`unordered_map`）。同時也想起 Ransom Note 學到的「key 種類固定又少時，陣列比 hash map 更快」，`n` 的範圍固定小，決定用陣列。

#### 程式碼階段：`std::array` 的大小限制

寫成 `std::array<int, n-1> store;`——`std::array` 的大小必須是**編譯期常數**，`n` 是執行期才知道的函式參數，這樣編不過。這個限制是 `std::array` 跟 `std::vector` 最大的差異：`vector` 大小才能在執行期動態決定。同時陣列大小本身也算錯了（`n-1` 應該要開到能容納索引 `n-1`，至少要 `n`）。

最終沒有真的改用 `vector`，而是想到**不需要存整個歷史記錄，只需要記住前兩個值**，直接用兩個滾動變數（`p1`、`p2`）取代整個容器，空間複雜度從 O(n) 進一步降到 O(1)，是比原本規劃的陣列記憶化版本更好的解法。

#### 邊界情況：`n=2` 算錯

判斷式一開始寫 `if(n > 2)`，導致 `n=2` 被歸類到「直接回傳 1」的分支（跟 `n=0`、`n=1` 混在一起），但 `n=2` 正確答案是 `2`，不是 `1`。用 `n=2` 驗證抓出這個問題，修正成 `n >= 2` 才讓 `n=2` 也能進到迴圈正確計算。

### 1️⃣ 語法概念

- `std::array<T, N>` 的 `N` 必須是編譯期常數，不能是函式參數這種執行期變數；大小需要動態決定時用 `std::vector<T>`
- 這次的容器選擇糾結（`pair` → 陣列 → 最後發現根本不需要容器，兩個變數就夠）整理進 `container_selection.md` 速查表

### 2️⃣ 邏輯與複雜度

- 最終版本 O(n) 時間、O(1) 空間，是這題的最優解
- **不是所有 DP 題都需要把整個歷史記錄存下來**：這題每一步只依賴「前兩個」狀態，不需要完整的陣列，用滾動變數就能達到 O(1) 空間，這是動態規劃常見的空間優化技巧

### 3️⃣ 演算法 / 資料結構盲點

- 這題是動態規劃（DP）的入門題，核心是把問題轉換成遞迴關係式（想「最後一步」），並用記憶化（存下算過的子問題答案）避免暴力遞迴的指數級重複計算。完整概念、常見誤區獨立做成 `dynamic_programming.md`
