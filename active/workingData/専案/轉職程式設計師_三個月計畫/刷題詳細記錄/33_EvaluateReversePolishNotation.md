### 我的解法

```cpp
class Solution {
public:
    int evalRPN(vector<string>& tokens) {

        stack<int> s;

        for(int i = 0; i < tokens.size(); i++ ){
            if( tokens[i] == "+" || tokens[i] == "-" || tokens[i] == "*" || tokens[i] == "/"){
                int r1 = s.top();
                s.pop();
                int r2 = s.top();
                s.pop();

                if(tokens[i] == "+"){
                    s.push(r2+r1);
                }else if(tokens[i] == "-"){
                    s.push(r2-r1);
                }else if(tokens[i] == "*"){
                    s.push(trunc(r2*r1));
                }else if(tokens[i] == "/"){
                    s.push(trunc(r2/r1));
                }
            }else{
                s.push(stoi(tokens[i]));
            }
        }

        return s.top();
    }
};
```

- 時間複雜度：O(n)
- 空間複雜度：O(n)（stack 最壞情況裝下所有數字）

### 解題過程

#### 虛擬碼階段：從兩個 FIFO queue 收斂到單一 stack

一開始提出「數值跟運算符號各自用一個 FIFO queue，維護一個暫存值，每取出一個運算符號就跟暫存值運算」的設計。用 `["4","13","5","/","+"]`（正確答案 `6`）反例：這個設計會讓 `/` 錯誤地拿暫存值 `4` 去跟 `13` 運算（算出 `4/13=0`），但 `/` 其實該作用在 `13` 跟 `5` 之間。點出核心問題：把數值跟符號拆成兩個獨立佇列，會遺失「運算符號在原始序列中的位置」這個資訊——運算符號該作用的對象是「離它最近、還沒被用掉的兩個值」，不是「累加值 + 下一個排隊的值」。

改成「後進先出」（單一 stack），數字 push、遇到符號 pop 兩個運算再 push 回去，重新驗證 `["4","13","5","/","+"]` 正確算出 `6`。

#### 程式碼階段：多輪除錯

**C 類**：
1. `tokens[s]` 誤用 stack 當索引，應為 `tokens[i]`
2. `s.pop()` 沒有回傳值（C++ 跟 C# 不同），要先 `s.top()` 讀值再 `s.pop()` 移除
3. `soti(...)` 拼字錯誤，應為 `stoi(...)`
4. `switch` 不能用在 `std::string` 上（只能用整數類型），且 `case : "+"` 語法本身也錯（冒號位置），改用 `if/else if` 鏈
5. `return s[0];`：`stack` 沒有 `[]`，要用 `s.top()`
6. `elseif` 打成一個字，應為兩個字 `else if`

**A 類**：
7. 判斷「是數字還是運算符號」一開始用 `tokens[i][0]-'0' >= 0` 這種看第一個字元轉數字正負的方式，用 `"-3"` 反例點出會被誤判成運算符號（負數的第一個字元是 `-`，轉數字後是負值）。最終改成直接跟四個運算符號字串做相等比較（`tokens[i]=="+"` 等），順便解決了 `"-3"` 誤判的問題（`"-3"` 跟 `"-"` 是不同字串，不會混淆）

### 1️⃣ 語法概念

- `stack::pop()` 是 `void`，沒有回傳值；`switch` 不支援 `std::string`；`stack` 不支援 `[]` 索引——這幾個都是 `stack.md` 已經記錄過的坑，這次一次踩了三個
- 判斷 token 是數字還是運算符號，直接跟已知的四個運算符號字串做相等比較，比「解析第一個字元」更準確、也更不容易漏掉負數這種邊界情況

### 2️⃣ 邏輯與複雜度

- O(n) 時間、O(n) 空間，是這題最優解
- pop 出來的兩個值順序要注意：`r1` 是先 pop 出來的（stack 頂端，也是原始序列裡**較晚**出現的運算元），`r2` 是第二個 pop 出來的（較早出現的運算元）。減法/除法要用 `r2 op r1`（先出現的在前），順序顛倒會算出相反的結果

### 3️⃣ 演算法 / 資料結構盲點

- 第一次遇到「後綴表示式求值」，直覺想把數值跟符號拆開成兩個獨立序列分開處理，沒有意識到「運算符號要作用在哪兩個值」這個資訊必須靠**單一序列裡的相對位置**（用 stack 的後進先出天然保留）才能正確重建，拆開反而遺失了這個資訊。之後遇到「順序/位置本身帶有意義」的題目，優先想清楚拆分資料是否會丟掉必要資訊，再決定要不要拆
