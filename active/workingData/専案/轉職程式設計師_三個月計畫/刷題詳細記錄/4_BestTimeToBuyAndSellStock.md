## 複習 #1 — 2026-08-10

- 狀態：有Bug（思路方向靠討論修正，程式碼也靠討論排除兩個問題，不算獨立一次過）
- 花費時間：10 分鐘

### 我的解法

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int minVal=0;
        int maxDif=0;

        if(prices.size()==0)
            return 0;

        for(int i = 0 ; i < prices.size() ; i++){
            if(i == 0){
                minVal = prices[i];
            }else{
                if(prices[i] < minVal){
                    minVal = prices[i];
                }else{
                    if(maxDif < (prices[i] - minVal))
                    maxDif = prices[i] - minVal;
                }
            }
        }

        return maxDif;
    }
};
```

- 時間複雜度：O(n)（一次掃描，理論下限，這題不可能更快）
- 空間複雜度：O(1)（只用兩個變數）

### 解題過程

#### 最初的想法：用 Tree（BST）找最大值減最小值

最初提出的方向是「把價格依序塞進 BST，找最右側節點當最大值、找最左側當最小值，回傳兩者相減」。這個想法**致命的盲點**在於：

**BST 是依照數值大小排列節點的，這個過程會完全丟棄「時間順序」。** 而這題的核心限制正是「必須先買才能賣」——最小值出現的時間點一定要在最大值之前，不能反過來。用反例驗證：`prices = [7,6,4,3,1]`，全域最大值是 `7`（第一天）、最小值是 `1`（最後一天），如果只是單純「最大減最小」會算出 `6`，但正確答案是 `0`（不存在先買後賣還能賺錢的組合，因為最大值發生在最小值之前）。

任何「先依值排序、再找極值」的做法（BST、排序、Map 找 max/min）都會踩到同一個問題，因為排序這個動作本身就會打亂原始的時間順序。這題真正需要的是**保留原始順序、由左到右單一掃描**，邊掃邊維護「目前為止的最小值」跟「目前為止能拿到的最大獲利」——這是一種和「找最大最小值」完全不同的思考模式：不是找兩個極值再相減，而是**邊走邊更新一個「目前最佳解」**。

轉向正確方向之後，額外確認了「用 Tree/Map 複雜度是否過高」的疑慮，釐清單一掃描 O(n) 才是這題的理論下限與最優解，順序問題解決的同時，複雜度也跟著變成最優。

#### 程式碼階段的兩個 bug

1. `prices.Size()`——大寫開頭是 C# PascalCase 命名習慣，C++ STL 全小寫，要用 `prices.size()`
2. `maxDif = prices[i] - minVal;` 一開始沒有跟目前記錄的 `maxDif` 比較，每次算出新的差就直接覆蓋，導致中途出現的較大獲利被後面較小的差覆蓋掉。修正成 `if (maxDif < (prices[i] - minVal)) maxDif = ...;`，只有算出來的差比目前記錄的還大才更新

### 1️⃣ 語法概念

- `.Size()` vs `.size()`：C++ STL 全部是全小寫命名，C# 的 PascalCase 習慣（`Size()`、`Count`）不能直接搬過來用，這是跨語言轉換容易犯的低階錯誤

### 2️⃣ 邏輯與複雜度

- 最終版本 O(n) 時間、O(1) 空間，是這題的最優解
- 「更新目前最佳解時要跟舊值比較，不能直接覆蓋」是這題的關鍵邏輯，跟單純的「賦值」思維不一樣——任何「持續追蹤最佳/最大/最小」的題型，都要留意是「比較後更新」還是「無條件覆蓋」

### 3️⃣ 演算法 / 資料結構盲點

- 核心盲點：**排序類資料結構（BST、Map、排序陣列）會丟棄原始順序**，只要題目的限制條件跟「順序」有關（例如「先買後賣」「子序列」「必須遞增出現」），用排序類結構去找極值就要先停下來想清楚順序資訊會不會被破壞
- 這題真正的解題模式是「單一掃描 + 邊走邊維護目前最佳解」，跟 Two Sum（Hash Map 查表）、Valid Parentheses（Stack 配對）、Merge Two Sorted Lists（雙指標尾端合併）是不同的第四種套路，之後遇到「求某種最大獲利/最大差值，且有順序限制」的題目可以直接聯想到這個模式
