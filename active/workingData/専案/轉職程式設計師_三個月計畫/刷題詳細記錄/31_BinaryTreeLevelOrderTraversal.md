### 我的解法

```cpp
class Solution {
private:
    vector<vector<int>> rtn;

    void DFS(TreeNode* root, int depth){
        if(root == nullptr){
            return;
        }else{
            DFS(root->left, depth+1);
            DFS(root->right, depth+1);
            while(rtn.size()<=depth){
                rtn.push_back({});
            }
            rtn[depth].push_back(root->val);
        }
    }

public:
    vector<vector<int>> levelOrder(TreeNode* root) {
        int depth = 0;

        if(root == nullptr){
            return rtn;
        }

        DFS(root, depth);

        return rtn;
    }
};
```

- 時間複雜度：O(n)
- 空間複雜度：O(n)（輸出 + 遞迴呼叫堆疊，最壞情況樹高 O(n)）

### 解題過程

#### 虛擬碼階段：DFS vs BFS 的選擇討論

主動確認邊界情況（空樹、單一節點、不平衡樹、歪斜樹），並要求三組測資先手動驗證。決定嘗試用 DFS 做，提問「為什麼網路上大多用 BFS」，討論後理解：兩者 Big-O 複雜度相同（都是 O(n)），BFS 只是「概念上天生契合、正確性直覺」（queue 天生就是一層一層處理），不是效能差異；DFS 一樣可行，只是需要額外帶深度參數、且需要自己確信「先左後右的走訪順序，配合深度分類，最終每層內部順序仍正確」這件事成立。

第一版虛擬碼描述模糊：提到「直到該節點左右都是 nullptr，才是葉節點，開始進行回傳」，經提問確認這句話是否代表「只有葉節點的值會被記錄」——確認需要修正成每個節點（不只葉節點）走訪到當下都要記錄。

#### 程式碼階段：第一次嘗試用迭代 + 單一 `prev` 變數，結構性失敗

第一版用 `while` 迴圈搭配單一個 `prev` 指標模擬回溯，用具體例子（3 層小樹）trace 出兩個結構性問題：
1. 檢查 `root->right` 之前，`root` 已經被改指到 `root->left` 的子節點，導致原本節點的右子樹永遠遺失
2. 單一個 `prev` 變數只能記住「上一步」，沒辦法正確回溯超過一層

回頭複習了自己之前 Diameter of Binary Tree（第 21 題）、Maximum Depth of Binary Tree（第 23 題）的遞迴寫法，確認遞迴本身（透過呼叫堆疊）天生解決「回溯」的問題，改用遞迴重新設計。

#### 遞迴版本：兩輪除錯

1. **`depth++` 後置遞增的副作用**：`DFS(root->left, depth++)` 跟 `DFS(root->right, depth++)` 連續使用 `depth++`，每次呼叫不只傳值給子呼叫，還悄悄修改了自己這一層的 `depth` 變數本身。用節點 `9`（真實深度應為 `1`）trace 出：兩次 `depth++` 執行完，自己的 `depth` 已經被改成 `3`，導致記錄到錯誤的層。改成沒有副作用的 `depth+1`
2. **`rtn` 動態補大小只用 `if` 判斷一次，補不夠**：`rtn` 一開始是空的，第一次走訪到深度 `1` 的節點時，`rtn.size()=0`，`if` 只補一次（變成 `size=1`），但存取 `rtn[1]` 需要 `size>=2`，還是超出範圍。改成 `while` 迴圈持續補，直到大小足夠為止

兩處都修正後，用範例樹跟自己準備的歪斜樹測資完整 trace，確認正確。

### 1️⃣ 語法概念

- `vector<vector<T>>` 想用不確定存不存在的索引直接存取，要用 `while(v.size()<=idx) v.push_back({})` 持續補到足夠大，只用 `if` 檢查一次不夠應付「一次跳超過 1」的情況
- 遞迴傳遞索引/深度這類參數時，要用沒有副作用的 `depth+1`，不能用 `depth++`（後置遞增會連帶修改自己手上的變數，導致同一層內多次使用時互相干擾）

### 2️⃣ 邏輯與複雜度

- O(n) 時間、O(n) 空間（含遞迴呼叫堆疊，最壞情況歪斜樹達到 O(n)），BFS 版本則是 O(n) 時間、O(n) 空間（queue 最多同時裝一層的節點數）
- DFS 做層序走訪的關鍵：記錄動作放在遞迴呼叫子節點「之後」（後序）依然正確，因為左子樹一定會在右子樹之前完整跑完（含記錄自己），同一層的先後順序天然由左到右，不需要把記錄動作移到呼叫子節點之前

### 3️⃣ 演算法 / 資料結構盲點

- 第一次嘗試用迭代（非遞迴）方式做樹的走訪，用單一變數模擬回溯，結構性失敗——樹的遞迴回溯本質上需要記住「完整的路徑」，只有真正的遞迴（呼叫堆疊）或明確的 Stack 容器能做到，單一變數不夠。之後想避開遞迴、自己手動迭代時，先確認需不需要「回溯超過一層」，需要的話直接想到用 Stack 或維持遞迴，不要嘗試用單一變數硬做
- DFS 也能完成「層序」這種聽起來像是 BFS 專屬的任務，只要额外帶一個深度參數——遇到「看起來一定要用某種資料結構/走法」的題目，可以想一下有沒有辦法用自己更熟悉的技巧（這裡是遞迴）改造出來，兩種思路都有其效能與直覺上的取捨
