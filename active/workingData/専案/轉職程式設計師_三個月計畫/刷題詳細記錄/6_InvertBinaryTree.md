### 我的解法

```cpp
TreeNode* invTN(TreeNode* root){

    if(root==nullptr){
        return {};
    }

    if(root->left != nullptr){
        invTN(root->left);
    }

    if(root->right != nullptr){
        invTN(root->right);
    }

    auto p = root->left;
    root->left = root->right;
    root->right = p;

    return{root};

}
```

- 時間複雜度：O(n)（每個節點恰好走訪一次）
- 空間複雜度：O(h)（h 是樹的高度，遞迴呼叫堆疊的深度；最壞情況歪斜樹是 O(n)，平衡樹是 O(log n)）

### 解題過程（這題卡最久，60 分鐘分成三個階段）

#### 階段一：題目整個誤解成 BST 插入問題

一開始把「Invert Binary Tree」理解成「輸入一串數值，依照大小規則一個個比對插入，建成一棵二元搜尋樹」，寫了整套「比對、往左/往右插入」的虛擬碼。

**核心誤解**：這題的 `root` 一開始就已經是一棵**完整的樹**，不是一串待插入的原始數值，題目要做的是把**已經存在**的樹，每個節點的左右子節點對調（鏡像翻轉），完全不需要任何「比大小、決定插入位置」的邏輯。這個誤解花了不少時間才釐清，釐清之後前面寫的虛擬碼整個作廢，重新開始想。

#### 階段二：只走「一路向左」「一路向右」兩條路徑，漏掉中間轉彎的節點

重新理解題目後，第一次設計是：定義 `TN_P`（父節點）手動追蹤「上面是誰」，分別沿著「一路向左走到底」跟「一路向右走到底」這兩條路徑往下走到葉節點，再往回走的過程中依序交換每個節點的左右指標，最後根節點單獨交換一次。

**這個設計的結構性盲點**：二元樹的分支可以任意組合「左轉、右轉」，不是只有兩條極端路徑。用一棵不規則的樹驗證（`8` 底下 `3` 的右子節點是 `6`，`6` 底下還有 `4`、`7`）——節點 `6` 是「先左轉、再右轉」才會走到的節點，完全不在「一路向左」或「一路向右」這兩條路徑上，這個設計永遠不會處理到它，它的子節點永遠不會被交換，結果是錯的。原本舉的例子之所以看起來可行，是因為那棵樹形狀剛好規則（每個非葉節點都恰好落在最左或最右路徑上），是巧合，不是方法本身正確。

#### 階段三：改用遞迴，程式碼階段的連環坑

轉向「每個節點都呼叫自己去處理左右子節點」的遞迴設計後，虛擬碼一次就對了，但轉成程式碼時連續冒出好幾個問題：

1. **停止條件寫反**：一開始寫「`root->left && root->right`（兩個子節點都有）才算葉節點，直接返回」——這跟葉節點的定義（兩個子節點都**沒有**）完全相反，而且沒有檢查 `root` 本身是不是 `nullptr`，對空指標取值會直接崩潰。修正成只需要「`root == nullptr` 就回傳」，因為對 `nullptr` 做交換本來就是無害的空操作，不需要額外判斷葉節點
2. **`var` 不是 C++ 語法**：`var p = root->left;`，`var` 是 JS/C# 的關鍵字，改成 `auto` 或明確寫 `TreeNode*`
3. **用 `==` 代替 `=`，交換完全沒發生**：`root->left == root->right;` 是比較，不是賦值，這兩行實際上什麼都沒做
4. **嚴重觀念錯誤：對暫存指標呼叫 `delete`**：`p` 只是暫時存著「原本 `root->left` 是誰」的變數，跟 `root->left` 指向同一個節點，這個節點仍然是樹的一部分。對 `p` 呼叫 `delete`，等於把這個還在使用中的節點連同底下的子孫節點整個從記憶體銷毀，樹會壞掉。`p` 用完後什麼都不用做
5. **函式結尾缺 `return`**：正常執行路徑沒有回傳值，`TreeNode*` 回傳型別要求所有路徑都要有回傳
6. **`reutrn` 打字錯誤**：拼字錯誤導致編不過

### 1️⃣ 語法概念

- 遞迴的核心：函式呼叫自己處理更小範圍的同一個問題，「處理完子節點後自動跳回上一層繼續」是函式呼叫機制（call stack）內建的行為，不需要手動定義變數追蹤「上面是誰」
- `auto` 用來讓編譯器自動推導型別，這裡用來宣告暫存指標變數
- 交換兩個指標值，用的是一般的三步驟暫存交換法（`p = a; a = b; b = p;`），關鍵是要用 `=`（賦值）不是 `==`（比較）
- `delete` 只該用在「這塊記憶體確定不再需要」的情況，暫存指標（跟既有資料指向同一塊記憶體）不能亂 `delete`

### 2️⃣ 邏輯與複雜度

- 最終版本 O(n) 時間、O(h) 空間，是這題的標準解法
- 遞迴呼叫子節點跟交換自己左右指標的**先後順序其實不影響正確性**（因為交換自己的指標，不依賴子節點內部是否已經處理完），這題不管先遞迴再交換、還是先交換再遞迴都可以

### 3️⃣ 演算法 / 資料結構盲點

- 核心盲點：遇到「樹狀結構、每個節點都要做同一件事」的題目，直覺要想到**遞迴**，而不是自己手動維護一個「父節點」變數去模擬「回到上一層」——這件事語言本身的函式呼叫機制已經幫你做了
- 這題也是一個提醒：拿到題目先確認清楚**輸入到底是什麼**（這題的 `root` 已經是完整的樹，不是待處理的原始數值），方向搞錯會導致後面大量時間白費
