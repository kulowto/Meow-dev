### 我的解法

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {

        ListNode* list3;

        if(list1 == nullptr){
            return list2;
        }else if(list2 == nullptr){
            return list1;
        }else{

            list3 = new ListNode(-1);
            ListNode* tail = list3;

            while (list1 != nullptr || list2 != nullptr){

                if(list1->val == list2->val){
                    tail->next = list1;
                    tail = tail->next;
                    list1=list1->next;
                }else if( list1->val > list2->val){
                    tail->next = list2;
                    tail = tail->next;
                    list2=list2->next;
                }else{
                    tail->next = list1;
                    tail = tail->next;
                    list1=list1->next;
                }

                if (list1 == nullptr){
                    tail->next = list2;
                    return list3->next;
                }
                if (list2 == nullptr){
                    tail->next = list1;
                    return list3->next;
                }

            }

            return list3->next;

        }

    }
};
```

- 時間複雜度：O(n+m)（n、m 分別是兩條串列的長度，各自只走一次）
- 空間複雜度：O(1)（沒有配置新節點，重複利用 L1、L2 原有的節點，只是重新接線）

### 解題過程（除錯軌跡，這題花最多時間的地方）

這題整體卡在兩個大階段：**設計方向選錯**、**指標語法不熟**。

#### 階段一：虛擬碼設計方向繞了遠路（往中間插入 vs 只接尾端）

一開始設計是「把 L1 整段複製進 L3，再把 L2 的節點一個一個插入 L3 中間正確的排序位置」。這個方向連續改了 4 輪，每輪都冒出新的結構性問題：

1. 完全沒有 `prev`（前一個節點）的概念，導致「插入到某節點前面」這個動作沒辦法真的接回鏈結串列
2. 比較條件寫錯對象（拿 L3 現在的值跟 L3 後面的值比，而不是拿 L2 的值去比）
3. 沒想清楚「每次插入 L2 節點時，搜尋位置要不要從頭開始」——這個沒釐清會讓複雜度從 O(n+m) 退化成 O(n×m)
4. 往後搜尋、走到最後一個節點之後，會去讀一個不存在節點的值；插入完也忘記更新指標，導致連續插入時前一個插入的節點會被覆蓋遺失

在冒出第 4 個結構性問題之後，改換方向：**兩個指標各自追蹤 L1、L2，一個 tail 指標永遠只接在輸出串列的尾端**。這個設計完全不需要 prev、不需要往回改連結、不需要重新搜尋——換方向之後虛擬碼只再花 2 輪就收斂（補上「起始就有一方是空串列」的邊界情況、確認 tail 要跟著往前移動）。

**這階段最大的學習**：卡住超過 2 輪還在同一個設計裡冒新坑，值得停下來問「有沒有更簡單的設計」，而不是把原本的坑一個個補完。

#### 階段二：虛擬碼轉成 C++ 語法，指標觀念不熟造成的連環錯

1. `ListNode* next = &list3;`——`list3` 本身已經是指標，對它取 `&` 會變成 `ListNode**`（指標的指標），型別對不上。搞混了「複製指標的值」（`next = list3;`）跟「取得指標變數本身的位址」（`&list3`）
2. `null` 不是 C++ 語法，是 C#/Java 習慣帶過來的，C++ 要用 `nullptr`
3. `esle if` 打字錯誤
4. `if(list1->val == null)`——判斷「串列是否為空」查錯對象，應該檢查 `list1` 這個指標本身是不是 `nullptr`，而不是先假設節點存在、去看它裡面的 `val`（這樣寫如果 `list1` 真的是空的，`list1->val` 這一步就先崩潰了）
5. `list3->next = &(list1->val);`——最嚴重的觀念錯誤：`list1->val` 是節點裡的 `int`，對它取 `&` 得到 `int*`，但 `next` 要的是 `ListNode*`，型別完全不符。核心誤解是「接節點」跟「接節點裡的某個值」搞混了，應該直接用 `list1`（已經是指向整個節點的指標）
6. 連續兩輪都寫成 `list3->next = ...`，而不是 `tail->next = ...`。`list3` 是固定不動的 dummy 節點，每次用它接東西等於直接覆蓋，會把前一輪已經接上去的節點弄丟——這題用具體例子（`list1=[1]`、`list2=[1]`）驗證過，能直接看到節點消失的過程
7. 就算換成 `tail->next = ...` 之後，還漏了「接完之後要讓 `tail` 本身也往前移動到剛接上去的節點」這一步，導致跟第 6 點一樣的「同一個位置被覆蓋」問題，只是原因換了
8. `return list3;` 忘記多走一步，回傳的是 dummy 節點本身（值是 `-1`），應該是 `return list3->next;`
9. `while` 迴圈裡的 `return` 都寫在迴圈內部，迴圈外面沒有保底的 `return`，編譯器沒辦法證明所有路徑都有回傳值，噴 `-Werror,-Wreturn-type`，需要在迴圈後面補一個 `return list3->next;`

### 1️⃣ 語法概念

- `ListNode` 節點結構：`->val` 取值、`->next` 取下一個節點的指標
- `list1`（變數本身）跟 `list1->next`（節點裡的欄位）存在不同的記憶體位置：前者是區域變數存的位址，後者是該節點內部欄位存的另一個位址，兩者指向不同的節點
- `&` 只在「這個變數本身不是指標，想拿到它的位址」時才用；如果變數本身已經是指標，直接賦值就是複製位址，不需要再取一次 `&`
- Dummy head 技巧：先建一個沒有意義的起始節點，`tail` 指標從它開始往後接，最後回傳 `dummy->next`（或 `dummy.next`），跳過起始節點本身

### 2️⃣ 邏輯與複雜度

- 最終版本時間複雜度 O(n+m)，空間複雜度 O(1)，是這題的標準解法等級
- 第一階段「往中間插入」的設計，就算修好所有坑，最壞情況也會退化成 O(n×m)（如果沒解決「重新搜尋 vs 接續搜尋」的問題），比「只接尾端」的設計差一個量級——這也是換方向的關鍵原因之一，不只是因為坑多，是因為效率也更差

### 3️⃣ 演算法 / 資料結構盲點

- 核心洞察：兩條**已排序**的串列要合併，只要同時維護兩個指標各自往前走、每次接較小的那個到輸出串列尾端，完全不需要「插入到中間」。看到「合併兩個已排序的東西」，之後可以直接想到這個雙指標尾端合併的套路
- `tail` 指標「接完要立刻往前移動」這個動作，本質上跟 Valid Parentheses 那題「`while` 條件要記得讓它改變，不然無窮迴圈」是同一類盲點——**任何用來追蹤目前狀態的變數，做完動作後都要記得同步更新它**，這條已經記進跨題目盲點彙總
