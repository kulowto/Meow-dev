## 複習 #1 — 2026-08-10

- 狀態：有Bug
- 花費時間：20 分鐘

### 我的解法

```cpp
#include <cctype>

class Solution {
public:
    bool isPalindrome(string s) {

        string alnumS = "";

        for (int i = 0; i < s.length(); i++){
            if( isalnum(s[i])){
                alnumS += tolower(s[i]);
            }
        }

        if(alnumS == ""){
            return true;
        }

        for (int i = 0; i < alnumS.length(); i++){

            int midNum = alnumS.length()/2;

            if (alnumS [i] != alnumS[(alnumS.length()-1)-i]){
                return false;
            }else{
                if(i == midNum || (alnumS.length()-1)-i == midNum){
                    return true;
                }
            }

        }

        return false;

    }
};
```

- 時間複雜度：O(n)
- 空間複雜度：O(n)（額外建立 `alnumS` 這份篩過的字串）

### 解題過程

#### 虛擬碼階段

1. **索引算錯（off-by-one）**：一開始用 `s.length()-I` 當作「從後面數過來第幾個」，但合法索引範圍是 `0` 到 `s.length()-1`，`I=0` 時算出 `s.length()`，直接超出範圍。用 `"abc"` 驗證抓出這個問題，修正成 `(s.length()-1)-I`
2. **題目定義沒確認清楚**：一開始寫「移除非英文的符號」，沒考慮到題目其實是「保留英文字母**跟數字**」，數字不該被當成符號移除掉。用 `"1a"` vs `"0p"` 兩個例子釐清「數字要不要保留」會直接影響答案，確認後改成保留英數字

#### 程式碼階段

1. **忘記轉小寫**：虛擬碼明明有寫轉小寫，第一版程式碼只有 `isalnum()` 篩字元，完全沒呼叫 `tolower()`，導致 `"Aa"` 這種應該是迴文的字串因為大小寫不同判斷失敗
2. **變數名打錯**：`alnums`（少了大寫 `S`）跟宣告的 `alnumS` 對不上，編不過
3. **空字串判斷放錯位置**：一開始把 `if(alnumS=="") return true;` 放在 `for` 迴圈**裡面**，但如果 `alnumS` 真的是空字串，迴圈條件 `i < 0` 從一開始就不成立，迴圈內容根本不會執行，這個判斷變成永遠碰不到的死碼，導致空字串會直接落到最後的 `return false;`——跟預期相反。搬到迴圈外面、最前面才對
4. **比較「字元的值」跟「索引位置」搞混**：中點判斷寫成 `alnumS[i] == midNum`，拿字元本身的 ASCII 值去跟索引數字比較，兩者意義完全不同。用 `"aa"` 走一次驗證，這樣寫永遠不會觸發中點條件，導致明明是迴文卻回傳 `false`。修正成比較索引本身：`i == midNum`

### 1️⃣ 語法概念

- `isalnum(c)`：`<cctype>`，判斷字元是否為英文字母或數字，回傳非 0/0。實際參數型別是 `int`，如果 `char` 是負數（signed char 遇到非 ASCII 字元）直接丟入是未定義行為，保險寫法是 `isalnum(static_cast<unsigned char>(c))`（這題輸入是標準 ASCII，實務上不會踩到，先知道有這個坑）
- `tolower(c)`：`<cctype>`，逐字元轉小寫，要搭配迴圈用，不是整個字串一次轉換

### 2️⃣ 邏輯與複雜度

- 目前版本 O(n) 時間、O(n) 空間（多建了 `alnumS` 這份篩過的字串）
- `midNum` 宣告在迴圈裡面，每次迭代都重算一次，值其實不會變，可以搬到迴圈外面算一次（小優化，不影響正確性）

### 3️⃣ 演算法 / 資料結構盲點

- 這題答案跟「對稱位置的字元是否相同」有關，屬於 [`order_vs_value.md`](../語法概念卡/order_vs_value.md) 框架裡「順序/位置重要」的類型，適合用雙指標直接在原始資料上操作，不需要額外複製一份篩選過的資料——目前這版「先篩選建新字串、再從頭比對」的做法可以再精簡成單一趟雙指標，見下方「可加強空間」

### 可加強空間

- **雙指標直接在原字串上做，不額外建字串**：兩個指標分別從頭尾往中間靠，遇到非英數字就跳過（只移動那一邊的指標），兩邊都是英數字才轉小寫比較。空間複雜度可以從 O(n) 降到 **O(1)**，也不用「篩選一趟 + 比對一趟」分兩趟做，一次雙指標夾逼就完成

## 複習 #2 — 2026-08-10

- 狀態：有Bug
- 花費時間：15 分鐘

### 我的解法

```cpp
#include <cctype>

class Solution {
public:
    bool isPalindrome(string s) {

        if(s == ""){
            return true;
        }

        int left = 0;
        int right = s.length()-1;

        while(left < right){

            while(!isalnum(s[left])&&left<right){
                left++;
            }

            while(!isalnum(s[right])&&left<right){
                right--;
            }

            if(tolower(s[left])!=tolower(s[right])){
                return false;
            }

            left++;
            right--;

        }

        return true;

    }
};
```

- 時間複雜度：O(n)
- 空間複雜度：**O(1)**（不再額外建立字串，直接用兩個指標在原字串上操作，比複習 #1 的 O(n) 空間進步）

### 解題過程

把複習 #1 的「先篩選建新字串、再從頭比對」改成雙指標直接在原字串上做，過程中連續踩了三輪同一件事：**跳過非英數字的迴圈要怎麼正確組合「還沒找到英數字」跟「還沒超出邊界」這兩個條件**。

1. **第一版兩層迴圈設計（`i` + `j`/`k`）**：一開始用 `for` 迴圈的 `i` 當外層計數器，另外用 `j`、`k` 兩個從不重置的偏移量疊加上去，模擬左右指標。這個設計本身就過度複雜，`j`、`k` 疊加造成同一組字元在不同輪被重複比對，而且跳過非英數字的 `while` 完全沒有邊界檢查——用 `s = "."` 這種全是符號、沒有任何英數字的輸入驗證，`j` 會一路遞增到超出字串範圍還繼續讀，是未定義行為。改成只用 `left`、`right` 兩個指標，不需要額外的 `i`
2. **改用兩指標後，跳過迴圈依然沒有邊界檢查**：`while(!isalnum(s[left])){ left++; }` 只檢查是不是英數字，沒檢查 `left` 有沒有超過 `right`。用 `s = ".."` 驗證，兩個符號、沒有英數字，`left` 會一路加到超出字串長度還在讀，一樣是未定義行為
3. **加邊界檢查，但位置放錯**：把 `left<right` 塞進 `isalnum()` 的括號裡（`isalnum(s[left]||left<right)`），變成把字元和布林值做 `||` 運算後的結果丟給 `isalnum()`，完全不是原本要表達的意思。邊界檢查要獨立在 `isalnum` 判斷之外
4. **位置修正了，但運算子用錯**：改成 `!isalnum(s[left]) || left<right`，但用 `s = ".ab"` 驗證，因為 `left<right` 這個條件在大部分情況下本來就是 `true`，用 `||` 的話只要它成立，整個條件恆真，`isalnum` 的判斷形同虛設，會把明明是英數字的 `'a'` 也跳過去，導致最終誤判成 `true`（正確答案是 `false`）。改成 `&&`（兩個條件都要成立才繼續找）才真正解決

### 1️⃣ 語法概念

- `&&` vs `||` 的選擇：「兩個條件都要成立才繼續」用 `&&`；「任一個成立就繼續」用 `||`。跳過非英數字這種「找到目標**或**超出邊界，兩者任一發生就該停」的情境，迴圈的**繼續條件**要用 `&&`（沒超出邊界 `&&` 還不是目標字元），跟「停止條件」是相反的概念，容易搞混
- 條件式要獨立成一個完整的布林運算式，不能把「布林條件」塞進另一個函式（例如 `isalnum()`）的參數裡面，兩者是完全不同層級的東西

### 2️⃣ 邏輯與複雜度

- 空間複雜度從複習 #1 的 O(n) 降到 O(1)，時間複雜度維持 O(n)，是這題真正的最優解
- 沒有邊界檢查的「跳過」迴圈，是這輪最危險的一類 bug：不會馬上噴出明顯的錯誤答案，而是在特定輸入（例如全是符號、沒有英數字）才會觸發超出範圍的存取，平常測資可能矇混過去，要刻意想「最極端的輸入」去驗證

### 3️⃣ 演算法 / 資料結構盲點

- 這次的盲點不是「不知道要用雙指標」（`order_vs_value.md` 框架已經內化），而是「雙指標內層還要再加一層跳過邏輯時，兩個條件怎麼正確組合」——雙指標搭配「跳過不符合條件的元素」是很常見的複合套路（之後遇到類似「雙指標 + 過濾條件」的題目，要記得內層跳過迴圈永遠要同時檢查邊界，不能只檢查目標條件本身

### 跟上次相比

- 上次記錄的「可加強空間」（雙指標、O(1) 空間）這次做到了
- 新出現的問題：雙指標本身的技巧掌握了，但複合了「跳過」邏輯後，條件式的組合方式（`&&`/`||`、邊界檢查擺放位置）連續卡了三輪，是這次真正的學習重點
