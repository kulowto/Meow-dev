### 我的解法

```cpp
class MyQueue {
private:

    stack<int> sIn;
    stack<int> sOut;

    void shiftStack(){
        if(sOut.empty()){
            while( !sIn.empty()){
                sOut.push(sIn.top());
                sIn.pop();
            }
        }
    }

public:

    MyQueue() {

    }

    void push(int x) {
        sIn.push(x);
    }

    int pop() {
        shiftStack();
        int front = sOut.top();
        sOut.pop();
        return front;
    }

    int peek() {
        shiftStack();
        return sOut.top();
    }

    bool empty() {
        return sIn.empty()&& sOut.empty();
    }
};
```

- 時間複雜度：均攤 O(1)（每個元素一生只會被 `push`/`pop` 各一次，單次 `pop()` 最壞情況可能 O(n)，但攤平到整個生命週期是 O(1)）
- 空間複雜度：O(n)

### 解題過程

#### 邏輯設計：自己想通的部分

一開始直覺想到「用兩個 Stack，把一個的內容整個倒進另一個，順序就會反過來，變成 FIFO」，這個核心技巧是自己想到的。討論過程中修正了兩個細節：

1. 一開始以為倒過去之後，`stOut` 還需要用「FIFO 概念的方法」處理——澄清後理解到不需要，倒完之後直接用 `stOut` 原本的 Stack 操作（`top`/`pop`）就自動符合 FIFO，不需要額外設計新函式
2. 一開始沒想清楚「什麼時候該把 `stIn` 倒進 `stOut`」，一度以為「每次 `push` 完就要倒」，用具體例子（`push(1), push(2), pop()`）驗證發現這樣會把新舊順序混在一起、順序算錯。修正成**只有 `stOut` 是空的時候才倒**，`stOut` 不是空的時候什麼都不用做，直接用現有內容操作

#### 卡住的地方：類別裡私有函式的語法

邏輯完全想清楚了，但卡在「私有輔助函式（`shiftStack()`）在類別裡怎麼定義、怎麼被同一個類別的其他成員函式呼叫」這個語法本身，最後參考了網路上的寫法才完成。

### 1️⃣ 語法概念

- **類別（class）裡私有函式的定義與呼叫**：私有函式跟其他成員函式一樣寫在類別內部（放在 `private:` 區塊），呼叫時直接用函式名稱即可（例如 `pop()` 裡面直接寫 `shiftStack();`），不需要額外的物件前綴——因為是同一個類別內部的呼叫，跟外部呼叫成員函式（需要透過物件）不一樣。這塊語法是這次真正卡住的地方，需要額外找時間複習類別（class）的基本語法（`private`/`public` 區塊、成員函式怎麼互相呼叫）
- `stack<int>` 當作類別的成員變數（不是區域變數），讓它在整個物件的生命週期內持續存在，跨越多次 `push`/`pop` 呼叫都能保留狀態——這跟之前 Linked List Cycle 學到的「共用狀態不能宣告成會被重置的區域變數」是同一個道理，只是這裡用「類別成員變數」這個機制正確做到了

### 2️⃣ 邏輯與複雜度

- 均攤 O(1)，是這題的標準解法
- 「只在 `stOut` 空的時候才搬」是這題效率的關鍵：如果每次都搬，會退化成每次操作都要重新排一次序

### 3️⃣ 演算法 / 資料結構盲點

- 兩個 Stack 互相搬移可以模擬出 Queue 的行為，核心是利用「倒一次容器，順序就會整個反過來」這個特性——LIFO 反過來就是 FIFO，這個技巧本身是這題最重要的洞察，這次是自己直接想到的，沒有卡住
