# 文件類型系統設計決策：T1 / T2

> 本文件記錄 T1（重點摘要）與 T2（可執行流程）兩種文件類型的設計動機、規則定義與架構決策。
> 實作檔案位於：SSOT `MA/ssot/core/document-types.md`，指令 `~/.claude/commands/t1-*.md` / `t2-*.md`

---

## 背景與動機

使用者常需要從外部來源（影片、文章、規範文件）產出兩種性質截然不同的文件：

- **知識消化型**：快速掌握內容核心，方便回顧與分享
- **執行操作型**：確保可直接照做，AI 與人都能遵循執行

過去沒有統一的規則，每次產出品質不一致。本系統建立固定的規則與 prompt 模板，確保一致性。

---

## 設計決策總覽

### 決策 1：兩種類型命名為 T1 / T2

**T1 = 重點摘要文件**：以理解與回顧為目的，注重閱讀節奏與資訊密度。
**T2 = 可執行流程文件**：以執行與驗證為目的，確保人與 AI 都能照做。

**Why**：使用者在日常溝通中以 T1/T2 縮寫，建立共同語言降低溝通成本。

---

### 決策 2：T2/T3/T4 為三種獨立類型

| 類型 | 用途 | 核心差異 |
|------|------|---------|
| T2 | 將網路規範/原則轉為可執行流程 | 著重決策點與例外處理 |
| T3 | 安裝與設定引導文件 | 有選項時呈現選項樹，執行交給 AI |
| T4 | 驗證/覆盤文件（流程單元測試） | 著重通過條件與錯誤處理，主要由 AI 閱讀使用 |

**Why**：三種情境的輸入性質與輸出結構差異太大，同一模板無法涵蓋，強制分類確保品質。最終命名為獨立的 T2/T3/T4，而非 T2-A/B/C，讓各類型地位對等且易於延伸。

---

### 決策 3：SSOT 只放輕量定義，完整 prompt 按需調用

**SSOT（常駐）**：T1/T2/T3/T4 定義 + 觸發邏輯規則（約 30 行）
**按需調用（Skill Command）**：各類型完整 prompt 模板（各約 50-100 行）

**Why**：SSOT 每次啟動都會載入，放完整 prompt 會增加 context 負擔。只需讓 AI 知道「有這些類型、怎麼觸發」，執行時才載入完整規則。

---

### 決策 4：觸發邏輯走 SSOT 自然語言判斷

使用者說「幫我做總結」→ AI 自動判斷類型，**不確定就立即停止詢問**，不自行假設。

**Why**：使用者偏好不需記指令的自然語言觸發。但錯誤判斷類型比多問一句更糟，所以不確定時強制詢問。

---

### 決策 5：T1 + T2 可同時產出，但須先確認

同一來源若同時包含 T1 和 T2 性質的內容：
1. 告知使用者
2. 進行章節分類（每章標記歸屬類型）
3. 呈現分類結果請使用者確認
4. 確認後才執行

**Why**：錯誤的類型判斷會導致整份文件需要重做，先對齊成本遠低於事後修正。

## T1 完整規則

### 章節結構

- 影片/來源有提供章節 → 直接沿用
- 無章節 → AI 自行判斷，原則：**一個章節只服務一個主題**

### 每章格式

```
[核心一句]
用一句話清楚說明整個章節的核心

[具體展開]
若原出處有具體案例或方法 → 重點化說明原出處內容
若無，或內容較冗長/深度時 → AI 補充比喻，須符合：
  - 國中生也能理解的概念
  - 不超過 30 字的句子
  - 以生活上大家接觸得到的東西為例
  並以以下格式標示（前後須各空一行）：

  [AI 補充比喻]
  這就像... (範例)

```

### 文件結構（由上至下）

1. **[事前]** 看這份內容的動機與預期收穫（AI 視內容判斷是否適合加入）
2. **[總結]** 全片/全文結論（結論先行，麥肯錫溝通原則）
3. **[章節 × N]** 每章核心句 + 具體展開
4. **[金句]** 原文 + 中文翻譯（逐條列出）
5. **[事後]** AI 視內容判斷是否適合加入：
   - 值得思考的問題
   - 行動方案與建議

### 其他規則

- **僅使用原出處內容**：AI 自行補充的內容（如比喻）須以 `[AI 補充比喻]` 標示
- **資訊密度**：有消化，但不過度簡化；每章節可獨立閱讀

## T2 完整規則（共用基礎）

### 三條核心原則

1. 不是「提煉精華」，而是「確保可執行」
2. 讀者（人類 + AI）看完要能直接照做
3. 必要欄位：步驟編號、前置條件、判斷點、例外處理

### T2 特定結構

```
前置條件
步驟（編號）
  └─ 決策點（if X → Y, else Z）
例外處理
驗證步驟
```

### T3 特定結構

```
需求確認（硬體/軟體/權限）
選項樹（呈現給使用者選擇）
安裝步驟（編號，AI 執行）
驗證確認
故障排除
```

### T4 特定結構

```
驗證目標（預期結果定義）
驗證項目清單（逐條，含通過條件）
通過 / 不通過 判斷標準
錯誤處理與回報格式
```

## 觸發邏輯（完整）

```
使用者要求產生文件
  ↓
判斷內容類型
  ├─ 明確只需 T1（知識理解/摘要）
  │     → 直接執行 T1
  ├─ 明確只需 T2（規範→可執行步驟）→ 直接執行 T2
  ├─ 明確只需 T3（安裝/設定）→ 直接執行 T3
  ├─ 明確只需 T4（驗證/覆盤）→ 直接執行 T4
  ├─ 不確定類型
  │     → 停止，詢問使用者
  └─ 同時包含多種類型
        → Step 1：告知使用者
        → Step 2：章節分類（每章標記 T1 / T2 / T3 / T4）
        → Step 3：呈現分類結果請使用者確認
        → Step 4：確認後才執行產出
```
